Fundamentos de programación
- **Programar**: escribir una secuencia de instrucciones para que un ordenador realice una tarea específica.
- **Programa**: secuencia de instrucciones.
- **Lenguaje de programación**: conjunto de reglas y símbolos para escribir programas.
- **Lenguaje máquina o código máquina**: instrucciones en formato binario (0 y 1) que ejecuta el procesador.
- **Código nativo**: código máquina propio de una arquitectura o plataforma concreta.

- **Lenguaje ensamblador:** utiliza mnemónicos para representar instrucciones.
- **Mnemónicos:** abreviaturas que representan instrucciones.
- **Lenguaje máquina:** único lenguaje que ejecuta directamente el procesador.
- **Ensamblador:** traduce lenguaje ensamblador a lenguaje máquina.
- **Lenguajes de bajo nivel:** lenguaje máquina y ensamblador.
- **Lenguajes de alto nivel:** COBOL, Pascal, FORTRAN, C, C++, Java, C#, Python.
- **Código fuente (source code):** programa escrito en un lenguaje de programación.
Compiladores y lenguajes de programación
- **Lenguajes de alto nivel:** fáciles de escribir, leer, comprender y modificar.
- **Traducción:** mediante compilador, intérprete o ambos.
- **Compilador (compiler):** traduce código de alto nivel a lenguaje máquina u otro lenguaje inferior.
- **Código compilado:** resultado de la compilación.
- **Intérprete (interpreter):** interpreta y ejecuta instrucciones sin compilar previamente todo el programa.
- **Bytecode:** código intermedio generado al compilar Java.
- **JVM:** máquina virtual que ejecuta el bytecode Java.
Componentes de un lenguaje de programación
- **Sintaxis (syntax):** reglas para escribir instrucciones válidas.
- **Semántica (semantics):** significado de las instrucciones.
- **Pragmática (pragmatics):** uso práctico del lenguaje.
- **Vocabulario:** palabras, símbolos y signos de puntuación.
- **Gramática:** reglas para combinar el vocabulario y formar instrucciones válidas.
Sintaxis, semántica y pragmática
- **Corrección sintáctica y semántica:** un programa debe estar bien escrito y tener un significado válido.
- **Ejemplo:** "La piedra se está riendo" es sintácticamente correcta, pero carece de sentido.
- **Pragmática:** estudia los usos del lenguaje de programación, sus efectos sobre los usuarios y sus aspectos prácticos.
- **Facilidad de implementación:** dificultad para desarrollar herramientas que lo ejecuten.
- **Idoneidad:** adecuación para una aplicación concreta.
- **Eficiencia:** aprovechamiento de los recursos.
- **Portabilidad:** facilidad para utilizarlo en diferentes plataformas.
- **Metodologías:** compatibilidad con distintas formas de programar.
Paradigmas de programación
- **Ejemplo:** un político propone leyes, un filántropo dona alimentos y un monje propone soluciones espirituales. Los tres abordan el mismo problema desde diferentes paradigmas.
- **Paradigma:** conjunto de conceptos e ideas que determina una forma de interpretar la realidad.
- **Objetivo:** encontrar soluciones prácticas y eficaces.
- **Importante:** ningún paradigma es el mejor para todos los problemas.
- **Paradigma de programación:** forma de pensar, analizar y organizar una solución antes de escribir código.

Componentes de un programa
- **Datos:** representan la información.
- **Algoritmo:** conjunto de pasos que trabajan con los datos para resolver un problema.

Tipos de paradigmas
- **Imperativo:** indica paso a paso qué debe hacer el ordenador.
- **Procedimental:** organiza instrucciones en procedimientos o funciones.
- **Declarativo:** describe qué resultado se quiere obtener.
- **Funcional:** organiza los cálculos mediante funciones.
- **Lógico:** utiliza hechos y reglas para obtener conclusiones.
- **Orientado a objetos:** organiza datos y comportamientos en objetos.
Paradigma imperativo
- **Estado del programa:** valores de los datos en un momento determinado.
- **Variables:** permiten acceder a valores almacenados en memoria.
- **Asignaciones:** permiten modificar el valor de una variable.
- **Estructuras de control:** controlan el orden de ejecución de las instrucciones.
- **Lenguajes:** FORTRAN, COBOL y C.

- **Lenguajes:** FORTRAN, COBOL y C.

Paradigma procedimental
- **Procedimental:** agrupa instrucciones en una unidad llamada procedimiento.
- **Procedimiento:** conjunto de instrucciones que se ejecutan como una unidad.
- **Llamar o invocar:** ejecutar un procedimiento.
- **Modularidad:** dividir un programa en partes independientes.
- **Reutilización:** utilizar las mismas instrucciones varias veces.
- **Organización:** estructurar mejor el código.
- **Efectos secundarios:** modificaciones de datos durante la ejecución.
- **Relación:** se basa en el paradigma imperativo, organizando las instrucciones en procedimientos.
- **Lenguajes:** C, C++, Java y COBOL.

Paradigma declarativo
- **Declarativo:** consiste en describir un problema sin especificar cómo llegar a la solución.
- **Imperativo:** se centra en cómo resolver el problema.
- **Declarativo:** se centra en qué queremos conseguir.
- **Subtipos:** funcional y lógico.
- **Imperativo:** los datos se modifican durante la ejecución del algoritmo.
- **Declarativo puro:** los datos de entrada permanecen sin cambios.
- **Algoritmo:** utiliza los datos de entrada para producir otros nuevos.
- **Efectos secundarios:** en el modelo puro, no se producen modificaciones de los datos originales.

Paradigma funcional
- **Funcional:** se basa en funciones matemáticas.
- **Función:** algoritmo que calcula un resultado a partir de datos de entrada.
- **Función pura:** no produce efectos secundarios.
- **Inmutabilidad:** los valores no se modifican; se obtienen nuevos valores.
- **Datos de entrada:** permanecen sin cambios.
- **Funciones:** permiten obtener nuevos valores.
- **Asignaciones:** en programación funcional pura no se utilizan para modificar variables.
- **Recursividad:** una función se llama a sí misma para resolver un problema.

Paradigma lógico
- **Lógico:** se centra en qué problema resolver, no en cómo resolverlo.
- **Programador:** describe el problema con la mayor precisión posible.
- **Programa:** encuentra el algoritmo necesario para resolverlo.
- **Axiomas:** conjunto de hechos y reglas de inferencia que constituyen una teoría.
- **Objetivo:** afirmación o teorema que se quiere demostrar.
- **Deducción:** razonamiento utilizado para demostrar el objetivo a partir de los axiomas.
- **Relación:** subconjunto del producto cartesiano de dos o más conjuntos.
- **Tupla:** elemento de una relación.
- **Lenguaje:** Prolog.

Paradigma orientado a objetos (POO)
- **POO:** programa formado por objetos que interactúan entre sí.
- **Objeto:** entidad que reúne datos y algoritmos.
- **Datos:** definen el estado del objeto.
- **Algoritmos:** definen su comportamiento.
- **Mensajes:** permiten la comunicación entre objetos y pueden provocar cambios en su estado.
- **Diferencia:** en POO, los datos y algoritmos se combinan en un objeto.
- **Clase:** unidad básica de programación que define cómo serán sus objetos.
- **Instancia:** objeto creado a partir de una clase.
- **Variables de instancia:** almacenan los datos propios de cada objeto.
- **Métodos:** definen el comportamiento y permiten consultar o modificar el estado.
- **Constructores:** permiten crear e inicializar objetos.
- **Estado:** conjunto de valores que posee un objeto en un momento determinado.
- **Instanciación:** proceso de crear un objeto.
- **Constructor:** establece los valores iniciales de sus propiedades. Una clase puede tener varios constructores.
- **Diseño:** los métodos disponibles se determinan según las necesidades del sistema.

Conceptos fundamentales de POO
- **Abstracción:** representar las características esenciales de un elemento.
- **Encapsulación:** agrupar datos y comportamientos, controlando el acceso a ellos.
- **Polimorfismo:** permitir que una misma operación tenga distintos comportamientos según el objeto.
- **Herencia:** crear clases que aprovechen características de otras clases.
